# صفحه‌کلید عددی — قواعد اختصاصی

> **پروژه:** GoldAccounting · **نوع:** کامپوننت بحرانی ورود داده
> این فایل بر `design-system/MASTER.md` **اولویت** دارد.

---

## نقش

کل ادعای محصول یک جمله است: **ثبت معامله باید از دفتر ۸۰ برگی سریع‌تر باشد** —
هدف زیر ۱۵ ثانیه. این کامپوننت تنها چیزی است که آن عدد را ممکن می‌کند.

کاربر **وسط معامله، ایستاده، با یک دست** کار می‌کند. طرف مقابل منتظر است.
هر ضربه‌ی اضافه و هر ثانیه انتظار مستقیماً به قیمت محصول می‌خورد.

## چرا کیبورد سیستم‌عامل کنار گذاشته شد

| مشکل کیبورد بومی | پیامد |
|---|---|
| نیمی از صفحه را می‌گیرد | پیش‌نمایش قیمت و فیلد بعدی دیده نمی‌شوند |
| تأخیر باز و بسته شدن دارد | بین هر دو فیلد یک مکث |
| چیدمانش قابل کنترل نیست | روی هر گوشی جای ارقام فرق می‌کند |
| کلید دامنه‌ای ندارد | `۷۵۰` `۹۹۵` `۷۴۰` باید رقم‌به‌رقم تایپ شوند |
| روی iOS صفحه را زوم می‌کند | چیدمان می‌پرد |

## چیدمان

```
┌─────────────────────────────────────────────┐
│  نوار پیش‌نمایش زنده                        │
│  ۱۲.۳۴۵ گرم · عیار ۷۵۰ →  ۲۸۴٬۹۱۹٬۷۴۳ ریال │
├───────────────┬───────────────┬─────────────┤
│      ۷        │      ۸        │      ۹      │   ┌──────┐
├───────────────┼───────────────┼─────────────┤   │ ۷۵۰  │
│      ۴        │      ۵        │      ۶      │   ├──────┤
├───────────────┼───────────────┼─────────────┤   │ ۹۹۵  │
│      ۱        │      ۲        │      ۳      │   ├──────┤
│      ٫        │      ۰        │      ⌫      │   │ ۷۴۰  │
├───────────────┴───────────────┴─────────────┤   └──────┘
│   ‹ قبلی        بعدی ›          تمام        │
└─────────────────────────────────────────────┘
```

- **ستون کناری وابسته به نوع فیلد است** — همان فضا، محتوای متفاوت:

| نوع فیلد | میان‌برها |
|---|---|
| عیار | `۷۵۰` `۹۹۵` `۷۴۰` `۹۲۵` `۹۰۰` |
| وزن | `÷۵` `×۲` `گرم↔مثقال` |
| مبلغ / مظنه | `۰۰۰` `۰۰۰۰۰` |
| تعداد | `۱` `۲` `۵` `۱۰` |

- `بعدی` و `قبلی` **داخل خود کیپد** — حرکت بین فیلدها بدون بستن کیپد.
- `تمام` کیپد را می‌بندد و فرم را تأیید می‌کند.

## اندازه‌ها

| مورد | مقدار | چرا |
|---|---|---|
| هدف لمسی هر کلید | **≥۴۸×۴۸px** | بالاتر از کف ۴۴px پروژه — این‌ها پرضربه‌ترین عناصر کل برنامه‌اند |
| فاصله‌ی بین کلیدها | **۸px** | جلوگیری از ضربه‌ی اشتباه روی کلید مجاور |
| موقعیت | **بالای Bottom Nav** | با توکن `--app-nav-h`، نه عدد دستی |

> فاصله‌ی کیپد از پایین با `--app-nav-h` محاسبه می‌شود. باگ شماره‌ی ۲
> گزارش نشست (هم‌پوشانی نوار اقدام و ناوبری) دقیقاً از هاردکدکردن همین
> عدد آمد؛ تکرار نشود.

## رفتار

- **پیش‌نمایش زنده‌ی قیمت** بالای کیپد، با `core-calc` در همان لحظه‌ی هر ضربه.
- **اعتبارسنجی لحظه‌ای** — خطا **زیر همان فیلد**، نه بالای فرم:
  عیار بین ۳۰۰ و ۹۹۹ · وزن > ۰ · مظنه > ۰
- **نگه‌داشتن `⌫`** = پاک‌کردن کل فیلد.
- **لرزش کوتاه** `navigator.vibrate(10)` — با محافظ وجود (iOS ندارد) و
  احترام به `prefers-reduced-motion`.
- **باز شدن با `transform`**، نه با تغییر ارتفاع محتوا → سهم CLS صفر.
- **استور جدا (Zustand)** تا هر ضربه کل صفحه را ری‌رندر نکند.

## مدل داده‌ی ورودی

مقدار به‌صورت **رشته‌ی ارقام** نگه‌داری و ویرایش می‌شود و فقط در لحظه‌ی
تأیید با تجزیه‌ی رقم‌به‌رقم به `bigint` تبدیل می‌گردد.

```
"12.345" گرم  →  12345n میلی‌گرم      (تجزیه‌ی رشته‌ای)
"۷۵۰"        →  750 عیار
```

**هرگز `parseFloat`، `Number()` یا `toFixed` روی ورودی کاربر.**
قاعده‌ی ESLint هر سه را خطا می‌دهد؛ تنها نقطه‌ی مجاز تبدیل،
`packages/core-calc/src/input.ts` است.

## دسترس‌پذیری

- هر کلید `aria-label` فارسی دارد.
- کیپد `role="group"` با `aria-label="صفحه‌کلید عددی"`.
- تغییر مقدار با `aria-live="polite"` اعلام می‌شود.
- **کیبورد فیزیکی هم کار می‌کند** (دسکتاپ گالری‌دار): ارقام، `Backspace`،
  `Tab`، `Enter`، `Escape`.

## تعارض‌های حل‌شده

| توصیه‌ی اسکیل | تصمیم | دلیل |
|---|---|---|
| **«`inputmode='numeric'` بگذار تا کیبورد عددی سیستم باز شود»** (Forms → Mobile Keyboards) | **رد** | این دقیقاً همان چیزی است که کنار گذاشته‌ایم. ما `inputMode="none"` و `readOnly` می‌گذاریم تا کیبورد سیستم **باز نشود**. توصیه‌ی اسکیل برای فرم‌های عمومی درست است؛ برای ابزاری که هدفش ثبت زیر ۱۵ ثانیه است، غلط. |
| «Default keyboard for all inputs = Don't» | **پذیرفته با تفسیر** | ما اصلاً کیبورد سیستمی نداریم؛ روح توصیه (کیبورد مناسبِ نوع داده) با کیپد دامنه‌ای **بهتر** برآورده می‌شود. |
| ✅ «حداقل ۸px فاصله بین اهداف لمسی مجاور» (Touch Spacing) | **پذیرفته** | `gap-2` بین کلیدها. |
| ✅ «Bulk actions به‌جای تک‌ردیفی» (Data Entry) | **خارج از دامنه** | مربوط به جدول‌هاست، نه ورود عدد. |
| انیمیشن و micro-interaction فراوان (MASTER) | **رد** | تأخیر ضربه تا رنگ‌آمیزی باید زیر ۱۰۰ms بماند. تنها بازخورد: تغییر رنگ آنی + لرزش ۱۰ms. |
| `hover` برای حالت کلیدها (MASTER) | **رد** | محصول لمسی است؛ فقط `active:`. |

## معیار پذیرش

- روی **اندروید میان‌رده‌ی واقعی**: ورود وزن + عیار + مظنه **زیر ۸ ثانیه**
- کیبورد سیستمی **هرگز** باز نشود — Chrome اندروید **و** Safari iOS
- تأخیر ضربه تا رنگ‌آمیزی **زیر ۱۰۰ms** (اندازه‌گیری با `performance.now()`)
- سهم CLS باز شدن کیپد **صفر**
- تستی ثابت کند مسیر ورودی هیچ‌جا از float عبور نمی‌کند
